### Описание и обоснование шагов на роадмапе

1. Разработать схемы данных для микросервисов медицинского, финтех-домена и ИИ-домена
   * Нужно чётко понимать, какие данные будут передаваться.
   * Без этого невозможно передача в DataHub или построение витрин.
2. Настроить выгрузку данных из микросервисов через Kafka
   * Нужно наладить каналы передачи данных.
   * Kafka станет основой событийной передачи изменений.
   * Для старых источников временно поддерживается интеграция через Apache Camel.
3. Развернуть и настроить Kafka как базовую интеграционную платформу
   * Запустить инфраструктуру для потоковой передачи данных.
   * Это основа для реального времени в ETL/ELT процессах.
4. Развернуть новое хранилище данных (S3 + Apache Iceberg + Nessie)
   * Необходимо хранилище для потоков и исторических данных.
   * Iceberg обеспечивает поддержку версионности и эффективную аналитику.
5. Развернуть и настроить DataHub
   * Каталогизация всех данных от микросервисов до витрин.
   * Нужно для прозрачности lineage и ускорения поиска данных.
6. Настроить пайплайны ETL/ELT через Airflow
   * Обеспечить чистку, трансформацию и загрузку данных в Data Lakehouse.
7. Развернуть движок Dremio для доступа к данным в Lakehouse
   * Чтобы аналитики могли писать SQL напрямую к данным без промежуточных баз.
   * Ускорение доступа и уменьшение затрат на инфраструктуру.
8. Передавать метаданные из микросервисов и пайплайнов в DataHub
   * Для создания полного lineage и управления качеством данных.
9. Построить базовые витрины данных на Dremio и подключить BI-инструменты (Tableau)
   * Начать выдавать бизнесу первую аналитику по новой архитектуре.
   * Демонстрация быстрой ценности.
10. Постепенно отключать старую интеграционную шину Apache Camel
    * После полной миграции источников на Kafka.
    * Упрощение архитектуры и снижение затрат на поддержку.
