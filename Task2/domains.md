### Разделение на домены
| Домен                | Описание, аргументация и преимущества |
|----------------------|----------------------------------------|
| Финтех-домен         | Включает данные по счетам, кредитам, транзакциям и платёжной истории. Является отдельной компанией с банковской лицензией и своими регуляторными требованиями Независимое развитие позволяет запускать новые финтех-продукты без изменений в DWH. Соответствует требованиям регуляторов. |
| Медицинский домен    | Содержит карты пациентов, истории болезней, данные о персонале и инвентаре. Это основной бизнес, где важна точность и безопасность данных. Связан с ИИ-доменом. Отделение позволяет развивать клинические процессы независимо от аналитической инфраструктуры. |
| ИИ-домен             | Включает предсказания, ML-модели и извлечённые признаки. Работает на Python, использует современные форматы (JSON, изображения). Должен быть гибким и масштабируемым. Позволяет быстро внедрять новые ИИ-сервисы без зависимости от других систем. |
| BI-домен (витрина)   | Включает витрины, агрегаты, отчёты и интерфейсы для бизнес-пользователей. Основной канал доступа к данным для сотрудников. Позволяет строить отчёты без участия IT. Повышает доступность данных и снижает нагрузку на легаси-системы. |
| Интеграционный домен | Включает старую шину данных на Apache Camel и потоки между системами. Необходим для обмена данными между доменами. Может быть модернизирован с переходом на Kafka или другие современные решения. Устраняет зависимости между системами. |

### Аргументация по разделению на домены
1) Изоляция ответственности. Каждая команда отвечает только за свои данные. Это ускоряет разработку, устранение ошибок и улучшает качество данных. Снижается time-to-market.
2) Независимое масштабирование и развитие. Например, финтех может перейти на свои форматы и инструменты, ИИ — использовать Python и Jupiter, BI — Tableau, не ломая систему в целом.
3) Гибкость в технологиях и инструментах. Один домен может работать с S3 и Iceberg, другой — с PostgreSQL или MongoDB. Нет жёсткой централизации.
4) Упрощение архитектуры. Вместо попытки вместить всё в один DWH — строится связная, но модульная система, где каждый блок может быть заменён или улучшен без каскадных изменений.
5) Учет юридических требований. Финтех и ИИ — юридически отдельные компании, с разными уровнями доступа, логами и согласиями.
6) Повышение прозрачности через DataHub. Каталог метаданных позволяет видеть, кто владеет каким источником, где находятся узкие места и как данные проходят по системе.
